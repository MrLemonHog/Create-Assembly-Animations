# Свои анимации

Анимация сборки — это ресурс-пак: фрагментный шейдер, который красит корабль, и JSON рядом с ним для названия,
звуков, настроек и эффектов.

**Содержание:** [1. Пак](#1-пак) · [2. Шейдер](#2-шейдер) · [3. JSON](#3-json) · [4. Эффекты](#4-эффекты)

## 1. Пак

```
my-animations/
  pack.mcmeta
  pack.png                                        необязательно, видна в настройках мода
  assets/my_pack/assembly_animations/wave.fsh     шейдер
  assets/my_pack/assembly_animations/wave.json    необязательно
  assets/my_pack/textures/particle/...            необязательно, картинки для эффектов
  assets/my_pack/lang/ru_ru.json                  необязательно, переводы
```

`my_pack` — пространство имён: строчные латинские буквы, цифры и `_`. Id анимации — `my_pack:wave`; из подпапки
`assembly_animations/lasers/blue.fsh` получится `my_pack:lasers/blue`.

**`pack.mcmeta`** (`34` — формат Minecraft 1.21.1):

```json
{
  "pack": {
    "pack_format": 34,
    "description": "Мои анимации сборки"
  }
}
```

**`wave.fsh`** — полоса света бежит вверх по кораблю:

```glsl
vec4 animate(Pixel pixel) {
    float front = Stage == ASSEMBLY ? Progress : 1.0 - Progress;
    float band = 1.0 - smoothstep(0.0, 0.1, abs(pixel.bounds.y - front));
    return vec4(pixel.color + vec3(0.4, 0.9, 1.0) * band, 1.0);
}
```

Положите папку в `resourcepacks` и включите пак — *Wave* появится в настройках мода.

Откройте страницу анимации в настройках и после каждой правки жмите `F3 + T`: шейдер пересоберётся, превью
обновится. Ошибки компиляции с номерами строк пишутся в `latest.log`.

В GLSL зарезервированы и неочевидные слова: `packed`, `input`, `output`, `sample`, `filter`, `active`, `flat`.
Переменная с таким именем даёт синтаксическую ошибку, которая не указывает на причину.

## 2. Шейдер

### Файл

В `.fsh` пишется только функция `animate`. Uniform-переменные, структура `Pixel` и функции ниже уже объявлены в
`assembly_animation.glsl`: `main`, `#version` и свои объявления не нужны.

`#moj_import <create_assembly_animation:effects.glsl>` добавляет `latticeHash`, `valueNoise`, `fbm`, `faceEdge`
(расстояние от точки на грани блока до края грани) и `desaturate`. Свои файлы: `#moj_import <my_pack:common.glsl>`
читает `assets/my_pack/shaders/include/common.glsl`.

### Пиксель

`animate` вызывается для каждого пикселя постройки и возвращает `vec4(цвет, alpha)`: alpha `0` оставляет пиксель
как есть, `1` заменяет его. Поля `pixel`:

| Поле | |
| --- | --- |
| `color` | что игра здесь нарисовала, с освещением мира |
| `pos` | позиция в блоках относительно физического сборщика |
| `block` | блок пикселя, целые числа |
| `inBlock` | позиция внутри блока, `0..1` по каждой оси |
| `bounds` | позиция внутри габаритов постройки, `0..1` по каждой оси (`.y` — высота) |
| `distance` | `0` у сборщика, `1` у самого дальнего блока |
| `random` | `0..1`, одно и то же для всех пикселей блока |
| `screen` | позиция на экране, `0..1` |
| `normal` | нормаль грани, у рёбер неточная |

Из-за неточной `normal` текстура, положенная по ней на грани, размажется. Грань пикселя находите по `inBlock`:
`min(pixel.inBlock, 1.0 - pixel.inBlock)` — расстояния до граней, наименьшее и есть грань. Если и оно больше примерно
`0.06`, пиксель не на грани куба, а на рычаге, пропеллере или крышке сундука.

Проще всего взять `onCubeFace(pixel, cube)`: истинно, когда пиксель на внешней грани полного куба, и кладёт клетку
куба в `cube`; на рёбрах не ошибается, рычаги, пропеллеры и прочие формы пропускает. `fullCubeAt(клетка)` и
`occupiedAt(клетка)` — стоит ли в клетке полный куб или любой блок.

### Uniform-переменные

| Uniform | |
| --- | --- |
| `Progress` | `0..1` — ход анимации |
| `Time` | секунды с начала |
| `Duration` | длительность из JSON, в секундах |
| `Stage` | `ASSEMBLY`, `ALIGNMENT` или `DISASSEMBLY` |
| `BoundsMin`, `BoundsMax` | габариты постройки, в координатах `pixel.pos` |
| `Reach` | расстояние от сборщика до самого дальнего блока |
| `Daylight` | `0` ночью, `1` в полдень |
| `ScreenSize` | размер окна в пикселях |
| `StartRight` | направление вправо по экрану в момент старта, в координатах блоков |
| `SceneColor`, `SceneDepth` | кадр игры, чтобы смотреть на другие пиксели |
| `Brightness` | настройка яркости у игрока |

Скорость и яркость игрока мод учитывает сам: скорость уже заложена в `Progress` и `Time`.

Повторное объявление этих uniform ломает шейдер. Заняты и эти имена: `Mask`, `Heights`, `Solids`, `SolidsGrid`,
`Fade`, `Area`, `Margin`, `InvViewProj`, `SceneToLocal`, `LocalToClip`.

### Три этапа

- `ASSEMBLY` — блоки становятся кораблём. `Progress` идёт от `0` до `1`.
- `ALIGNMENT` — рычаг дёрнули, корабль выравнивается перед разборкой. Может длиться до минуты, `Progress` всё это
  время `0`: ведите этап по `Time` и зацикливайте.
- `DISASSEMBLY` — корабль снова становится блоками. `Progress` идёт от `0` до `1`.

Разборка начинается сразу после выравнивания, поэтому её первый кадр должен совпадать с циклом выравнивания, иначе
на стыке будет рывок.

### Рисование вокруг постройки

С `"area": "screen"` в JSON шейдер работает и вокруг корабля, на расстоянии до `margin` блоков (по умолчанию `3`,
максимум `16`). Это нужно для всего, что выходит за корпус.

Дополнительные поля `pixel`:

| Поле | |
| --- | --- |
| `inside` | `1` на постройке, `0` вне её |
| `eye`, `ray` | луч взгляда, в координатах блоков |
| `depth` | расстояние по лучу до того, что уже нарисовала игра; всё дальше будет скрыто |

Вне постройки `pos`, `block` и остальные поля описывают землю или небо, поэтому проверяйте `inside`. Где рисовать
нечего, возвращайте alpha `0`.

Функции:

- `along(pixel, y)` — расстояние по лучу до плоскости на высоте `y` или `-1`, если луч упирается во что-то раньше.
  Точка попадания — `pixel.eye + pixel.ray * along(pixel, y)`.
- `topAt(vec2(x, z))` — высота постройки в колонке или большое отрицательное число, если колонка пустая. Через неё
  можно поставить что-то на палубу, например пламя.
- `buildAt(uv)` и `blockSpaceAt(uv)` — есть ли постройка в другой точке экрана и что там в координатах блоков.
- `toScreen(точка)` — куда точка из координат блоков попадает на экране. Результат учитывает соотношение сторон,
  сравнивайте его с `pixel.screen * vec2(ScreenSize.x / ScreenSize.y, 1.0)`.

Не ищите блоки рядом с пикселем в воздухе через `buildAt`: у соседних пикселей ответы разные, и рисунок выйдет
рваным. Используйте `topAt` или частицы.

### Прозрачность и исчезновение

`behind(pixel.screen)` — размытое окружение за постройкой в этой точке. `mix(behind(pixel.screen), pixel.color, 0.4)`
делает корабль полупрозрачным.

Переключатели в начале файла:

```glsl
#define RAW_OUTPUT
#define WRITES_DEPTH

vec4 animate(Pixel pixel) { ... }
```

- `RAW_OUTPUT` — цвет выводится как есть, без смешивания по яркости игрока. Своё свечение умножайте на `Brightness`.
- `WRITES_DEPTH` — появляется `float vanished`. `1.0` там, где постройки уже нет: эффекты за кораблём перестанут
  им закрываться.

Ещё есть `hash(vec3)` — случайное число, постоянное между кадрами, `luminance(vec3)` и `frame(...)` для текстур-лент.

## 3. JSON

`wave.json` лежит рядом с `wave.fsh`. Все поля необязательные; блоки кода ниже — куски этого файла.

### Название, длительность, свечение

```json
{
  "name": "Волна",
  "description": "По кораблю пробегает полоса света.",
  "author": "Вы",
  "duration": 2.5,
  "charge_color": [0.4, 0.9, 1.0]
}
```

- `name`, `description`, `author` — текст или ключ перевода из `lang` пака. Без `name` мод берёт ключ
  `<namespace>.style.<файл>`, а без него — имя файла: `wave.fsh` станет *Wave*.
- `duration` — секунды на сборку и на разборку, по умолчанию `3`, от `0.25` до `60`. Разная длина:
  `{ "assembly": 5, "disassembly": 7.5 }`; можно и формулу (см. [«Эффекты»](#4-эффекты)).
- `charge_color` — `[r, g, b]` от `0` до `1`: свечение сборщика, пока рычаг зажат.

### Текстуры

Подойдёт любая текстура: из игры, своего пака или другого мода. Ванильные пути учитывают ресурс-пак игрока.

```json
"textures": {
  "TntSide": "minecraft:textures/block/tnt_side.png",
  "Blast": [
    "minecraft:textures/particle/explosion_0.png",
    "minecraft:textures/particle/explosion_1.png"
  ]
}
```

В шейдере объявите их перед `animate`:

```glsl
uniform sampler2D TntSide;
uniform sampler2D Blast;
uniform float BlastFrames;
```

Имя — латинские буквы, цифры и `_`, начинается с буквы. Список склеивается в одну вертикальную ленту (кадры одного
размера) и получает `<Имя>Frames`; кадр достаёт `frame(Blast, BlastFrames, индекс, uv)`.

Анимированные ванильные текстуры вроде `fire_0.png` уже лента (16×512, 32 кадра), число кадров передавайте сами:
`frame(Fire, 32.0, mod(floor(Time * 20.0), 32.0), uv)` играет её с игровой скоростью.

Чтобы положить текстуру блока на грани, выбирайте грань по `inBlock`, как описано выше, и переворачивайте текстуру
на противоположных сторонах, чтобы не было зеркала.

### Звуки

```json
"sounds": [
  {
    "sound": "minecraft:entity.tnt.primed",
    "at": 0.0,
    "volume": 0.9
  },
  {
    "sound": "minecraft:entity.generic.explode",
    "time": 1.5,
    "pitch": 0.9
  },
  {
    "sound": "minecraft:block.portal.ambient",
    "every": 1.5,
    "stages": "alignment"
  }
]
```

| Поле | |
| --- | --- |
| `sound` | id звука, в том числе из вашего пака |
| `at` | когда играть, `0..1` по ходу анимации |
| `time` | или когда играть, в секундах от начала |
| `every` | повторять с этим интервалом в секундах |
| `from`, `to` | для `every`: в каких секундах повторять, по умолчанию всё время |
| `jitter` | для `every`: случайная добавка к интервалу, до стольких секунд |
| `volume`, `pitch` | по умолчанию `0.8` и `1.0` |
| `pitch_spread` | случайное повышение, до стольких |
| `stages` | этап или список: `assembly`, `alignment`, `disassembly` |

`time`, `every`, `from`, `to` и `jitter` могут быть [формулами](#формулы), например `"build_start / 20"`.

### Частицы

```json
"particles": [
  {
    "type": "minecraft:large_smoke",
    "from": 0.6,
    "to": 1.0,
    "rate": 25,
    "speed": 0.08
  },
  {
    "type": "minecraft:explosion",
    "where": "wave",
    "from": 0.5,
    "to": 0.8
  }
]
```

| Поле | |
| --- | --- |
| `type` | ванильная частица без своих настроек, например `minecraft:smoke` |
| `where` | `shell` (снаружи постройки, по умолчанию), `volume` (внутри) или `wave` |
| `from`, `to` | часть анимации, `0..1` |
| `rate` | частиц в секунду, по умолчанию `10`, максимум `200` |
| `speed` | скорость вылета, по умолчанию `0.02` |
| `chance` | для `wave`: доля блоков с частицей, по умолчанию все |
| `stages` | этап или список этапов |

`wave` выпускает по частице на каждый внешний блок волной от сборщика между `from` и `to`, например для
взрывов.

- По умолчанию звуки и частицы идут только на сборке и разборке; для выравнивания добавьте `"alignment"` в
  `stages`. Там `Progress` стоит, поэтому `at`, `from` и `to` не работают: для звуков берите `every`, частицы идут
  всё время.
- Превью в настройках не играет звуки и не выпускает частицы.
- Переключатели «Частицы» и «Звуки» у игрока действуют как обычно.

### Свои настройки

```json
"options": [
  {
    "id": "sparks",
    "type": "toggle",
    "default": true
  },
  {
    "id": "palette",
    "type": "choice",
    "values": ["gold", "ice", "ash"],
    "default": "gold"
  },
  {
    "id": "amount",
    "type": "slider",
    "min": 0.25,
    "max": 2,
    "step": 0.05,
    "default": 1,
    "format": "percent",
    "uniform": "Amount"
  }
]
```

- `id` — имя, под которым настройку читают [формулы](#формулы).
- `type` — `toggle`, `choice` или `slider`. `format` у ползунка — `percent`, `multiplier` или `number`.
- `uniform` — необязательно: шейдер получит настройку как `float` с этим именем (`0`/`1` у переключателя, номер в
  `values` у выбора, число у ползунка). Объявите: `uniform float Amount;`.
- `name` и `tooltip` — текст или ключ перевода. Без них берутся `<namespace>.style.<файл>.option.<id>` и `.tooltip`,
  для значений выбора — `...option.<id>.<значение>` (или `value_names`).

## 4. Эффекты

Картинки вокруг корабля, его предметы и тайминги, зависящие от размера, задаются в JSON формулами, а рисует их мод.
Эффекты видны и в превью.

### Формулы

Формула — строка в JSON: `"0.5 + 0.5 * cos(tau * time / 13)"`. Есть `+ - * / %`, сравнения, `&& || !`,
`a ? b : c` и функции:

`sin cos tan asin acos atan atan2 pow exp log sqrt abs sign floor ceil round fract mod min max clamp mix step
smoothstep smooth outback outcubic length hash noise fbm rand pick`, а также `pi` и `tau`.

- `mix(a, b, t)` и `smoothstep` — как в GLSL; `smooth(t)` — это `smoothstep(0, 1, t)`.
- `pick(i, a, b, c...)` — `i`-е значение, считая с `0`.
- `length(x, y, z)` принимает ровно три значения; для расстояния по плоскости передайте `0` вместо одного.
- `hash(x, y, z)`, `noise` и `fbm` дают те же числа, что `latticeHash`, `valueNoise` и `fbm` из `effects.glsl`.

Любая формула читает:

| Имя | |
| --- | --- |
| `time` | тики с начала (20 в секунду), с учётом скорости игрока |
| `stage` | `0` сборка, `1` выравнивание, `2` разборка |
| `reach`, `size`, `faces` | расстояние до дальнего блока, число блоков, число внешних граней |
| `lo_x`, `lo_y`, `lo_z`, `hi_x`, `hi_y`, `hi_z` | габариты постройки, в координатах блоков |
| `center_x`, `center_y`, `center_z` | их середина |
| `right_x`, `right_y`, `right_z` | `StartRight` |
| `id` каждой настройки | её значение |

### Значения корабля

```json
"vars": {
  "build_start": "16",
  "spread": "clamp(12 + reach * 0.7, 14, 36)"
},
"uniforms": {
  "BuildStart": "build_start / 20"
},
"duration": "(build_start + spread + 50) / 20"
```

- `vars` — свои имена, считаются по порядку; каждое видит предыдущие, все формулы после них — тоже.
- `uniforms` — значения для шейдера. Объявите их там: `uniform float BuildStart;`.
- `duration` и у звуков `time`, `every`, `from`, `to`, `jitter` принимают формулы (в секундах).

### Точки и рисунки

`effects` — список. Каждый эффект расставляет точки на корабле и в каждой что-то рисует.

```json
"effects": [
  {
    "on": "faces",
    "per_face": "2 * amount",
    "vars": {
      "life": "30 + 20 * rand(1)",
      "age": "time - 20 * rand(2)"
    },
    "when": "age >= 0 && age <= life",
    "draw": [
      {
        "sprite": "minecraft:glow",
        "glow": true,
        "x": "spot_x + normal_x * age * 0.02",
        "y": "spot_y + age * 0.01",
        "z": "spot_z + normal_z * age * 0.02",
        "size": 0.08,
        "alpha": "1 - age / life"
      }
    ]
  }
]
```

**Где точки** — `on`:

| `on` | |
| --- | --- |
| `faces` | случайные точки на внешних гранях, в среднем `per_face` на грань |
| `blocks` | середины блоков, доля `share` от `0` до `1` (при той же доле — те же блоки); `"items": true` — только блоки с предметом |
| `top` | одна точка: верхний блок ближе всего к середине |
| `center` | одна точка: середина постройки |

**Что знает точка** — её формулы читают ещё:

| Имя | |
| --- | --- |
| `spot_x`, `spot_y`, `spot_z` | где точка |
| `normal_x`, `normal_y`, `normal_z` | куда смотрит её грань (только `faces`) |
| `block_x`, `block_y`, `block_z` | её блок |
| `color_r`, `color_g`, `color_b` | средний цвет блока с тонировкой |
| `seed` | `0..1`, её случайное число |
| `rand(n)` | `n`-е случайное число точки |

`vars` эффекта считаются для каждой точки; не зависящие от `time` и настроек — один раз. `when` прячет точку, пока
равен `0`.

**Что рисуется** — `draw`, список записей; каждая рисуется в каждой точке:

| Поле | |
| --- | --- |
| `sprite` | картинка или список из `textures/particle/` пака: `"leaf"` — ваш `leaf.png`, `"minecraft:glow"` — ванильная |
| `item` | `true` — нарисовать предмет блока, как выброшенный |
| `x`, `y`, `z` | где рисовать |
| `size` | половина ширины картинки, в блоках |
| `roll`, `flip` | поворот и сжатие сбоку (`1` плашмя, `0` ребром), как у падающего листа |
| `r`, `g`, `b`, `alpha` | цвет, по умолчанию `1` |
| `picture` | номер картинки из списка |
| `glow` | `true` — добавляет свет, а не закрывает |
| `scale`, `yaw`, `pitch` | размер и поворот предмета (радианы) |
| `copies` | нарисовать запись столько раз, с `copy` от `0`: следы, слои, несколько искр на точку |
| `vars`, `when` | свои у записи |
